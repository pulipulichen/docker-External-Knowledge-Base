# rclone mount

## Recommended mount command

When mounting Google Drive with files that require random access or seeking (such as exported `.xlsx` spreadsheets or `.docx` documents), use `--vfs-cache-mode full`. Using `--vfs-cache-mode off` will cause `Input/output error` (EIO) when opening spreadsheets.

```bash
rclone mount gdrive:/documents /root/docker-External-Knowledge-Base/knowledge_base_files/.mnt/gdrive --daemon \
  --vfs-cache-mode full \
  --vfs-cache-max-age 24h \
  --drive-export-formats "docx,xlsx,pdf" \
  --vfs-read-chunk-size 32M \
  --vfs-read-chunk-size-limit 2G \
  --vfs-read-wait 180s \
  --disable-http2
```

Native Google Docs/Sheets still appear as **0-byte files** on the mount. The API therefore exports them with **`rclone copyto`** (Drive API) when rclone config is available, instead of reading the FUSE file.

## Private Google Sheets (no public link)

1. Mount the host rclone config into the API container (compose default: `/root/.config/rclone`). Override with `RCLONE_CONFIG_DIR` if needed.
2. Rebuild the API image so it includes the `rclone` binary.
3. In the knowledge base YAML, keep `path` as the local symlink/mount file and add `rclone_source`:

```yaml
path: goods.xlsx
rclone_source: "gdrive-goods:布丁宿舍日常用品 - AppSheet - 2020.xlsx"
section: 日常用品
```

If `rclone_source` is omitted and the file lives under `knowledge_base/files/.mnt/<remote>/...`, ingest tries `rclone copyto <remote>:<relative-path>` automatically.

Host-side one-shot export (same Drive API, no FUSE):

```bash
rclone copyto --ignore-size --drive-export-formats xlsx \
  "gdrive-goods:布丁宿舍日常用品 - AppSheet - 2020.xlsx" \
  ./knowledge_base/files/goods.xlsx
```

## Alternative: Direct Google Sheets URL (public or “anyone with the link”)

If the spreadsheet can be exported with a sharing URL, you do not need rclone mount:

```yaml
path: https://docs.google.com/spreadsheets/d/YOUR_SHEET_ID/edit?usp=sharing
description: Your knowledge base description
section: Sheet1
```
